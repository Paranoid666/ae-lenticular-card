# 渲染、恢复和验收

## 规格和混合帧率

按用户当前指定规格输出。原案例最终为 H.264 MP4、1280×720、60fps、12秒、720帧；早期预览为24fps、288帧。原1080p60工程仍保留，不把降规格预览误当高规格成片。

若已认可人物/天气的24fps预渲染放进60fps外层，人物仍然只有24fps时间信息。外层界面表达式和新粒子可以在60fps重新计算：检查相关嵌套合成的 Preserve frame rate 设置；关闭保留嵌套帧率不等于生成了低帧率视频里缺失的动作。用户要求人物也原生60fps时，应重新渲染人物源，或说明任何插帧方式及风险。

## 先试资源配置

原案例1080p60曾崩溃，关闭快速/多帧渲染不能保证解决。先检查内存、同时运行的 AE 进程和渲染方式；使用目标规格的短片（如30帧）估算耗时与内存峰值。

- 内存允许且用户接受时可用多帧渲染；控制并发，不同时启动多套全画幅重工程。
- 内存不足时先降低并发/CPU占用、限制缓存、分段渲染，或采用已认可的复杂源预渲染。保留全规格工程；降尺寸/帧率须符合用户授权。
- AE 偏好设置可能影响其他项目。优先临时任务配置，记录原设置、成功或失败后恢复；不要照搬历史脚本的全局偏好修改。
- 每段完成后保存工程与记录。连续崩溃时保留成功帧并调整策略，不无限重复同一个渲染配置。

## 可恢复序列

使用原生 TIFF/PNG 图像序列，将工作文件放在当前项目 `work/`。使用明确的合成帧号，如从0开始的 `card_[00000].tif`，分段渲染必须统一编号。

每段开始前确认工程、主合成、规格及目标目录；只启用本次队列项，不清除用户其他队列。渲染结束后核对编号、非空、实际尺寸与可解码性；文件存在不等于完成。重渲染损坏/缺失区间时也检查段边界，避免重复或跳帧。

序列编码前使用技能内的标准库脚本核对连续性：

```text
python scripts/check_frame_sequence.py --directory <帧目录> --prefix card_ --extension tif --start 0 --count 720
```

脚本不读取像素，不能替代图像解码或视觉验收。如果没有 Python，使用可用语言完成相同的帧号连续性检查。

## 编码与完整解码

使用本机已有 FFmpeg 或 PyAV。示例 FFmpeg 模板中的路径、帧数和帧率要替换为任务值；在 PowerShell 中分别引用路径参数，不拼接不受控 shell 字符串。

```text
ffmpeg -framerate 60 -start_number 0 -i card_%05d.tif -frames:v 720 -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p -movflags +faststart temporary.mp4
ffprobe -v error -count_frames -show_entries stream=codec_name,width,height,avg_frame_rate,nb_read_frames,duration -of json temporary.mp4
ffmpeg -v error -i temporary.mp4 -f null -
```

确保图像色彩解释与工程一致；原项目采用 BT.709 视频编码。不要仅设置颜色标签而忽略实际色彩转换。先输出临时成片，完整解码、规格核验与画面检查通过后再改为交付文件名；不覆盖既有已认可成片。

加入声音可使用已处理 WAV 和无声成片，`-c:v copy` 保留视觉结果，AAC 48kHz/192kbps是原案例参数。验证实际音轨、首尾时长、淡变和峰值，而不仅是确认封装器成功。

## 视觉验收

做含时间标记的抽帧对照：首帧、最后一帧、左右摆动极值、场景过渡开始/中间/结束、眨眼开闭、出屏粒子越界。像原项目那样抽取0/1/2/3/6/11.983秒可作起点，但具体时刻必须包含本次效果极值。

黑边检查先筛查四角和边缘异常，再在隐藏舞台底层背景的诊断副本中渲染 alpha，确认面板覆盖。深色AE界面可能正常，不能凭亮度阈值自动判定露底。顶部撕裂优先检查截图内是否残留静止照片；别用多加粒子遮住接缝。

与认可的基线帧比较人物颜色、头顶、固定脸部和衣服；检查发丝是否重影、断开，双眼是否同步，层次是否过密，粒子是否遮脸、边界重置，背景切换是否连续。观看成片确认运动节奏和音画感觉。

## 交付

交付 AEP、被引用的人物/背景/界面/预渲染/声音素材及 MP4，保持相对目录或正确引用。说明主合成、参数位置、输出规格，以及低帧率预渲染等已知限制。读取工程依赖或重新打开核对缺失素材；没有执行过的验证须单独标注。仅链接最终文件，避免把中间渲染缓存作为交付。
